# Affector 语义地图试用结果

日期：2026-09-28

完整原始响应、每次调用参数和逐项结果见 [affector_case_results.json](affector_case_results.json)；重跑入口见 [accept_affector_case.py](accept_affector_case.py)。

## 试验方法

- 从 ACProgram 当前源码、测试与 `docs/docs-829/04-mechanisms/engine/effect-trigger.md` 复制 8 个相关文件到临时目录；建立 `acprogram` 和 `other` 两个临时项目及 SQLite 数据库，试验结束后删除。
- 语义图包含 8 个节点、23 条关系和 31 条依据引用，覆盖事件重估、stat 轮询回退、激活沿、显式逐 Tick 效果、派生贡献；每项都关联实现、文档或测试文件角色。
- 对六个固定问题，路径/源码/预览路线 A 与语义地图路线 B 各重复 3 次。每项工具调用沿用 48,000 字节上限，预览最多 40 行。q4 另记录未修改时的新鲜地图复用，以及修改临时依据文件后的 stale 结果；测试完成后确认文件哈希已恢复。
- 建图读取 8 个依据文件并解析映射路径后，以单批 `update_map` 写入；请求、预览、路径解析与写入响应均留在 JSON 原始记录。45 ms 是这次本机临时图写入和凭据读取的辅助计时，不含全项目 refresh，也不代表长期性能。

## 结果

| 问题 | A：预览行 / 调用 | B：预览行 / 调用 | 实测结果 |
| --- | ---: | ---: | --- |
| 是否每 Tick 全量重估 | 40 / 3 | 160 / 7 | 概念入口能沿系统概念到达事件、轮询机制及其实现、测试；这份小型 fixture 中完整展开增加了读取量。 |
| 为什么 stat 仍需 Tick | 40 / 3 | 120 / 6 | 可直接找到轮询回退、`ConditionDepIndex` 和测试；本例未减少预览量。 |
| 条件重估与资源产出的边界 | 40 / 3 | 147 / 7 | 可到达 `perTickEffects`、`TickSystem` 和机制文档；本例未减少预览量。 |
| 依据是否新鲜 | 40 / 3 | fresh：0 / 3；stale：40 / 4 | A 没有新鲜度结论。B 在依据未变时直接回答 fresh，不需预览；fixture 内容变化后报告 stale、指出路径，再预览已变化文件。 |
| 尚未建图的主题怎么办 | 40 / 3 | 40–80 / 4–5 | 无概念命中后继续普通路径/源码检索；语义搜索没有阻断 fallback，但多一次概念查询。 |
| 两项目同名 ID 与相同路径 | 80 / 8 | 0 / 6 | 两项目中的同一节点 ID 返回各自摘要；相同路径解析出不同 File ID；`Private beta concept` 只在 `other` 命中。 |

## 结论与边界

当前收益集中在依据新鲜度、项目隔离和可复现的语义路径。前三个机制定位题在这个 8 文件 fixture 中，B 路线读取了更多关联文件；完整从系统概念遍历会展开过多来源，后续调用方应先选定机制概念，再只打开回答问题所需的角色文件。试验不支持“语义图普遍减少阅读量”或“服务带来稳定时延提升”的结论。

文件头仍写着“每 Tick 全量重估”，与当前 `AffectorEngine` 的事件定向重估和 stat/未知依赖轮询回退冲突；现行机制文档说明了两条路径，相关测试也覆盖 flag、跨实体 spotLevel 和 stat 回退。测试在本轮以只读方式检查，没有运行 ACProgram 测试或修改其文件。

试验结论只适用于所复制的 8 个文件与这张人工建图；不衡量 Affector 运行时性能，不证明所有状态写入/恢复链已安全，也不自动区分历史文档。保留当前查询能力；暂不扩展关系类型或自动建图，也不把本试验纳入 ACProgram 性能任务。
